# 路线图

## 已完成（v0.2.0）

- **核心层**：凭据解析、HTTP 与错误翻译、媒体处理、异步轮询、输出封装、成本记账（按秒 / 按张）
- **视频**
  - MiniMax H3（V2 直连）：文生视频 / 首帧 / 尾帧 / 首尾帧 / 多模态参考
  - Seedance（火山方舟）：文生 / 首帧 / 首尾帧 / 全模态参考 / 有声 / flex 离线档
  - 通义万相 Wan（百炼）：t2v / i2v / r2v / 参考生视频 / 反向提示词 / 多镜头
- **图像**
  - MiniMax `image-01` / `image-01-live`：文生图 / 图生图（人物参考）/ 风格预设
  - Seedream（即梦）：文生图 / 图生图 / 多图融合 / 组图 / 联网搜索
  - 千问 Qwen-Image：文生图 / 图像编辑 / **反向提示词** / 1–6 张
  - 通义万相 文生图：**异步**路径 / z-image-turbo
- 异步节点配套**任务查询**节点，避免本地超时后重复提交重复计费
- 价格表外置（`core/prices.json`，支持按秒与按张两种计价）+ 用量 JSONL 记账
- CI：Ruff + 语法编译 + 47 项协议与逻辑测试（不触网）
- **无 GPU 运行**：全部推理在云端，本地只做编排与文件收发

## 计划中

### 图像编辑的更多形态

- Seedream 的**边界框交互式编辑**与**角色一致性多图生成**
- Qwen-Image 的**图像编辑专用模型**（`qwen-image-edit` 系列）与多图输入
- MiniMax 的多张 `subject_reference`（当前官方只支持 1 张）

### 视频编辑类

- Seedance 2.x 的**延长视频 / 编辑视频 / 局部重绘**
- MiniMax 的 768P → 2K 再生成（`/v2/video_regeneration`）
- MiniMax 的 **Context-IR**（`/v2/h3_context_ir`）——把提示词结构化，官方称其"对最终输出质量至关重要"，
  本地跑没有这一步，是 API 画质更高的原因

### 工程化

- **批量节点**：读 JSON/CSV 分镜表，自动排队生成，按 `shot_xxx` 命名落盘
- **成本看板**：把 `usage.jsonl` 汇总成按天/按模型的花费表（视频按秒、生图按张混合统计）
- **Webhook 支持**：厂商支持 `callback_url` 时改为回调而非轮询
- **重试与幂等**：网络抖动重试，但不重复创建付费任务
- **素材上传助手**：给 Seedance / MiniMax 提供"本地文件 → 可公网访问 URL"的一键通道
  （目前只能手填 URL，是这两家最大的使用摩擦）
- **无 GPU 部署指引**：补一个 docker-compose / systemd 最小运行脚本

## 已知限制

- **节点未经真实 API 端到端验证**：开发环境没有各家的 Key。协议依据官方文档实现，
  CI 只做静态检查与协议构造测试。首次使用请用最便宜的档位跑一条（5 秒 / 最低分辨率 / 1 张图）。
- **Seedance / MiniMax 的本地图片建议走公网 URL**：这两家文档都只示范公网 URL；
  百炼明确支持内联 base64，Seedream 文档也明确支持。
- **四家的图片链接都只有 24 小时有效**：本项目在成功后立即下载到本地，
  但如果你手动取用链接请注意时效。
- **批量并发受限**：MiniMax 免费额度 2 个并发、付费 15 个；火山方舟按账号限流。
  批量务必串行。
- **价格表会过期**：`core/prices.json` 每个条目带 `checked` 日期，超过两三个月请复核。
- **`wan2.6-t2i` 节点只做文生图**：万相的图像编辑走 Qwen-Image / Seedream 节点。
